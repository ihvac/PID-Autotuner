# PID Autotuner 1.0.0 (beta)

> **This is a beta.** It is complete enough to use on real equipment, but it has not yet been through a season
> of daily work, and the Saia explorer in particular has so far only run against a simulated PCD. Expect bugs.
> **If you hit one, please report it** — what you did, what happened, and what you expected. The status bar
> message has a "Copy" button, and the Log module has "Open the log folder": the current day's log file from
> there says more than anything else you can send.

Tunes controllers in HVAC installations: it measures the response of the plant, computes PID settings and
writes them — over **BACnet/IP**, **Saia Ether-S-Bus** or **Modbus**. It also carries the BACnet browser,
alarms, trends, graphics, designation analysis and the Saia memory explorer.

| Download | For |
|---|---|
| `PidAutotuner-1.0.0-x64.msi` | install for all users: Start menu shortcut, firewall rule for UDP 47808 |
| `PidAutotuner-1.0.0-x64-portable.zip` | unpack and run; all data stays in a `Data` folder beside the program |

Windows x64. The .NET runtime is included, nothing else has to be installed.

**Before running it against a real plant.** The software writes to controllers. Every write is confirmed
first, controller settings are backed up and verified by a read-back, and a step test restores the previous
controller state when it ends, is aborted or fails. Even so, a step test moves a real process: run it only
where the plant can safely operate without control for the duration of the test, and set the safety limits on
the measured value before you start. In a beta this matters more, not less.

There is also a **read-only mode** that refuses every write at the transport — worth switching on before you
connect to an installation you are only allowed to look at.

The packages are not digitally signed, so SmartScreen warns about an unknown publisher.

Press F1 for the built-in manual. The interface is Polish, English or German.

## Known limits of this build

- The Saia explorer has been tested against a simulated PCD and the two PG5 symbol formats, **not yet against
  a live controller**.
- Saia timers, counters, DB blocks and texts are not readable: those S-Bus command codes have to be confirmed
  in the documentation rather than guessed, so they were left out.
- Modbus addresses are typed by hand — there is no point picker for Modbus as there is for BACnet and Saia.
- Tuning over Modbus has been tested end to end against a slave simulator, not against a live device.
- The graphics module is kept but no longer developed, and it has no background image.
